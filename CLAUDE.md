# CLAUDE.md

This repo holds two separate apps:

- **Repo root**: the Game Day Kickoff world (vanilla Three.js, deployed by the root `netlify.toml`). Leave it alone unless asked.
- **`brand-world/`**: the drop engine. A browser 3D world (desktop, mobile, Meta Quest Browser via WebXR) whose scenes come from designer GLBs and whose behavior and copy come from data. Everything below is about `brand-world/`.

Run all commands from `brand-world/`. Node 22.18+ (scripts are TypeScript run directly by Node; no tsx).

```bash
npm install
npm run dev            # validate + optimize assets, then Vite on :5173
npm run build          # prebuild runs validate + optimize; then tsc + vite build
npm test               # Playwright: builds, serves on :4173, runs e2e + unit specs
npm run test:update    # regenerate screenshot baselines (review the diffs)
npm run assets:placeholders   # regenerate blockout GLBs + placeholder video
VITE_XR_EMULATE=true npm run dev   # fake Quest 3 in desktop Chrome (dev only)
```

## The naming contract

The engine reads GLB node names and glTF `extras` (Blender custom properties) and wires behavior. Designers never touch code. Source of truth: `src/contract/rules.ts`, shared by the engine and the validator.

| Node name | Behavior | Required extras |
|---|---|---|
| `spawn_main` | Player start (exactly one) | none |
| `nav_walkable` | Walkable surface, baked into the navmesh, hidden at runtime | none |
| `collider_*` | Invisible blocking geometry, baked into the navmesh | none |
| `zone_*` | Trigger volume (mesh bounds). Fires `zone_enter`/`zone_exit`, preloads scenes | optional `preload` = comma-separated scene ids |
| `hotspot_*` | Clickable/tappable | `action` (registered action name), `contentId` |
| `screen_*` | Video texture target (needs UVs) | `mediaId` (key in `district.media`) |
| `door_*` | Loads another scene | `target` (scene id) |
| `plot_*` | Reserved for user-built spaces. Parsed, kept, no behavior in v1 | none |

Any other name is decoration. A name that looks like a botched contract name (`Hotspot_x`, `hotpsot_x`, `door-x`, `collision_x`, `spawn_side`) produces a warning, never a crash. Blender's `.001` suffixes are ignored. Unknown actions or missing extras warn at runtime and fail the validator.

Hidden kinds (nav, collider, zone) are moved to `LOGIC_LAYER` so pointer raycasts never hit them.

## Folder structure

```
brand-world/
  config/app.config.ts     active drop, min age, geo allow/block lists, scene residency
  config/budgets.json      per-scene budgets (validator + optimizer)
  content/<drop-id>/       SOURCE content (committed)
    district.json          scenes, GLB paths, media, links, collectibles, visibility
    copy.json              every user-facing string, with region overrides
    scenes/*.glb           designer exports (or placeholders)
    media/*                videos
  public/content/          GENERATED by optimize-assets (gitignored). Never edit.
  public/basis/            GENERATED KTX2 transcoder
  scripts/                 make-placeholders, validate-assets, optimize-assets, lib/
  src/
    boot/                  age gate, geo stub, device detection, BootFlow
    content/               district/copy loading, region overrides, visibility
    contract/              rules.ts, parseScene.ts, prefixes/<one file per prefix>
    interactions/          registry.ts, actions/<one file per action>, worldApi.ts
    loader/                GLTF loader (Meshopt + KTX2), scene cache with residency cap
    nav/                   recast navmesh (baked import, runtime fallback)
    player/                click-to-walk, WASD, iso camera, wall fade, XR rig
    store/world.ts         zustand: scene, unlocked, collected, session
    ui/dom, ui/xr, ui/panels   flat overlay, in-scene XR UI, shared panel model
    analytics/             typed events + pluggable adapter (console for now)
    net/adapter.ts         multiplayer interface only (null adapter)
    events/bus.ts          typed event stream that analytics and net subscribe to
    world/                 Canvas, active scene, screens, zones
  tests/e2e, tests/unit    Playwright specs and screenshot baselines
```

Keep files small and single-purpose. Behavior per prefix lives in `src/contract/prefixes/`, per action in `src/interactions/actions/`.

## How to add a new drop

1. Create `content/<new-drop-id>/` with `district.json`, `copy.json`, `scenes/`, `media/`. Copy the shape from `content/rolled-fresh/`.
2. Until art arrives: `npm run assets:placeholders -- <new-drop-id>` (generates plaza + factory blockouts; adjust or replace).
3. Set `activeDrop` in `config/app.config.ts`.
4. `npm run assets:validate` and fix everything it reports.
5. `npm run build && npm test`. Update screenshot baselines with `npm run test:update` if the scenes changed on purpose.

The engine must contain zero drop-specific content. If you need a drop-specific string, image, URL or id in `src/`, it belongs in `content/` instead.

## How to add a new action type

Add one file, `src/interactions/actions/<name>.ts`:

```ts
import type { ActionDef } from '../types.ts';

const action: ActionDef = {
  name: 'myAction',
  contentKind: 'links',          // which district/copy table contentId must exist in
  run: ({ contentId, district, world }) => { /* use world.* only */ },
};
export default action;
```

The registry (`import.meta.glob`) and the validator (reads the folder) both pick it up. Action files may only `import type`; they act through `WorldApi`, which keeps them loadable by Node for validation. If the action needs a new capability, add a method to `WorldApi` in `src/interactions/types.ts` and implement it in `worldApi.ts`. Analytics are emitted by the registry, so actions never call analytics. Add a `ContentKind` if it points at a new table, and map it in `scripts/validate-assets.ts`.

## Performance budgets

`config/budgets.json` (validator and optimizer read it):

- 100,000 triangles per scene (nav, collider and zone meshes excluded)
- 2048 px max texture dimension
- 8 MB per GLB after compression

Pipeline: `validate-assets` → `optimize-assets` (dedup, prune, weld, KTX2 ETC1S textures, Meshopt geometry, navmesh bake). KTX2 needs `toktx` (KTX-Software) on the build machine; without it textures fall back to WebP with a warning. Install it in CI for production.

Quest standalone rules:

- Navmesh is prebaked at build time. Runtime generation is a fallback and stalls the main thread on Quest.
- At most `sceneResidency` (2) scenes are kept parsed; older ones are disposed.
- One video plays with sound at a time; keep video at 1080p or below, H.264 MP4.
- No real-time shadows or post-processing. Bake lighting in Blender; the engine's hemisphere + directional light is for blockouts.
- Fixed foveation is on (`foveation: 1`).
- XR text uses troika (drei `Text`). Keep panel copy short, and set `district.fonts.xr` to a bundled font file; without it troika fetches a default font from a CDN.
- Meshopt over Draco: Draco decode is slow on Quest CPUs.

## Compliance rules (non-negotiable)

- No cartoon characters, candy or dessert imagery added by code. The engine's player marker is a plain capsule; placeholders are grey boxes. Art comes from designers only.
- No depictions of consumption, in code, placeholders, or copy.
- All user-facing copy comes from `copy.json` via `t()`. Never hardcode strings in components. (Only exception: the boot error shown if `copy.json` itself fails to load.)
- The age gate cannot be bypassed in production builds. The only skip (`?skipAgeGate`) is behind `import.meta.env.DEV`, which Vite compiles out; `tests/e2e/compliance.spec.ts` fails the build if the string appears in `dist/`. Do not add any other bypass, query flag, cookie or storage key that skips the gate. Under-21 results are remembered for the session.
- Geo blocking: Canada is blocked by default (`config/app.config.ts`). v1 is a stub because a static site cannot see the visitor's country; production needs an edge function feeding `lookupRegion()` in `src/boot/geo.ts`.
- Per-region visibility of nodes and content goes in `district.json` `visibility`, never in code.

Client-side gates are inherently inspectable. Real enforcement of age and region needs the edge layer.

## Conventions

- TypeScript strict, `erasableSyntaxOnly` (no enums, namespaces or parameter properties) so scripts run under Node type stripping. Use `.ts`/`.tsx` extensions in imports.
- New dependencies need approval.
- After each change: `npm run assets:validate`, `npm run build`, `npm test`, and report what passed.
